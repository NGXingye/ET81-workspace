# 0. 速览

> 速览：技能流水线的方向卡。只定目标、原则和补丁清单，规格内容由真实需求逐步补，不预先设计。
> 最大风险：每个特例都加一条命名 / 顺序约定或转完手改，补丁越积越多，规格膨胀成另一套行为树编辑器。
> 做对的标准：补丁清单只减不增；新需求要么推进规格一步，要么登记成带标记的手改出口。
>
> 门禁：`profiles/skill_pipeline.md`、`profiles/skill_sync.md`。机制和坑见 `skill_pipeline.md`、`skill_sync.md`、`ballistic.md`。本卡从属于源码和运行验证，冲突时按实际走并标「疑似过时」。

# 1. 目标与不变原则

目标：合法的上游设计 → 技能规格 → trunk 配置，trunk 零手改。覆盖约八成常规技能即可，特殊技能保留手改出口，不追求百分之百自动化。

- **上下游只经规格传信息**：不再新增靠文件名、挂点顺序、特效名推断的约定；已有的列在补丁清单里逐步收掉。
- **本地写法自写全字段**：不依赖共享写法或 Bridge 旧类型的缺省值（缺省 0、60 都踩过）。
- **时长单一时钟**：烘焙、形状、Buff 时长用同一套采样帧率换算，不各自取 Timeline 或缺省值。
- **转出配置只读**：trunk 上的转化产物不手改；必须手改的登记进补丁清单，并写明重转会被覆盖。

- 规格载体：`SkillEditor/LocalAuthor/skill_{id}.author.json`，只由工具生成（保存时按界面状态整份重写），禁手改；本地专用不入 svn，丢失无法从已提交内容重建。
- 字段以 `SkillPipelineAuthorFile.Doc/MotionRef/FireRef` 为准；读取镜像 `SkillPipelineBridge.AuthorDoc/AuthorFire`。
- 新增或改名字段：写入与读取两侧同任务改；JsonUtility 未知字段静默丢弃、缺失字段读为 0/空。
- 代号：`Launch` 0 近战 / 1 弹道 / 2 召唤 / 3 未设（转树只认 0、1）；`Carrier` 0 未设 / 1 形状 / 2 单位。
