# 0. 速览

> 速览：一技能可有多段动画 A/B/C；**00 负责姿态锁与动画切换编排**，再分别创建 **01 / 02 / 03…**（现状随机变体仍用 01/03/05）。**每个动画 Buff = 一个动画片段**的行为树：客户端只播该段动画与该段纯表现；服务器按该段时间轴加 Buff、下发业务 Buff、处理业务（含发射物阶段）。
> 最大风险：把多段塞进同一个 01；用父 Buff Duration 顶碰撞或阶段寿命；表现球与逻辑球销毁交接（已撤）。
> 做对的标准：问「01 本地技能树只处理一个动画？」→ **是**。多动画 = 00 编排多个「一动画一 Buff」，不是一个 01 里切片段。
>
> 门禁：`profiles/skill_pipeline.md`、`profiles/skill_sync.md`。机制见 `skill_sync.md`、`skill_spec.md`、`ballistic.md`、`root_motion.md`。本卡只定结构与边界；转化器未实现处标「待转化器」。基准只写在 `standards/`，不维护 Cursor Canvas。

# 1. 怎么运转

## 1.1 树结构（应然）

| 层 | 职责 | 边界 |
|---|---|---|
| **00（主 Buff）** | 子动作姿态锁；多段 A→B→C 时 **动画切换 / 编排在 00**，再创建对应动画 Buff | Duration ≈ 整段姿态窗口；不播具体片段；不做发射物阶段业务 |
| **01 / 02 / 03…（动画 Buff）** | **一 Buff 号 = 一个动画片段**的双端行为树 | 客户端：播该段动画 + 该段纯表现。服务器：该段时间轴逻辑（按时加 Buff、下发业务 Buff、发射物 Hold/Release/Track/Hit 等） |
| **业务子 Buff / SpellUnit** | 由动画 Buff（或 00 切段时）按时间创建；寿命自管 | **子业务寿命 ≠ 父 Duration 等式**；碰撞窗归节点持续，不跟父 Buff Duration 顶 |

**「01 本地技能树只处理一个动画？」→ 是。** 一技能多动画不是塞进同一个 01，而是 00 创建多个动画 Buff。这条 **00 → 01/02/03…** 线在结构上接得上；缺的是转化器按序出多段 Buff，不是模型本身。

## 1.2 编号：原则优于奇偶

- **原则**：一动画片段 ↔ 一个动画 Buff 号（优于具体用奇数还是连续号）。
- **现状（已实现）**：随机变体用奇数 **01 / 03 / 05**（`skill_spec`；`root_motion`：BTSetRootMotion 加在随机选出的动画 Buff 上，不在 master 00）。
- **顺序多段 A→B→C**：可用连续 **01 / 02 / 03**；如何占用「技能号×100+2 起、可覆盖号」→ **待与 `skill_sync` 可覆盖号规则对齐**。**不要假装 converter 已支持。** 未对齐前：手改或登记补丁出口，不扩 converter 默契。

## 1.3 时间与寿命边界

| 对象 | 谁定长短 | 不管什么 |
|---|---|---|
| 00 Duration | ≈ 整技能姿态 / 锁定期 | 不管单段业务窗是否结束 |
| 动画 Buff `LaunchStartTimeMs` / Duration | 该片段在整轴上的起点与长度（对齐动作） | 不管子碰撞、子飞行是否仍存活 |
| 节点持续（如 BTCastShape） | 碰撞 / 检测窗 | 不是父 Buff Duration |
| SpellUnit 阶段 | Hold → Release → Track → Hit 由节点 / 组件切换 | 不靠销毁再建第二颗球对齐时间 |

无「统一时间轴权威」跨表现树与逻辑树硬对齐（`_index`）。同一次施法两树可从同一 Buff 启动时刻起算，寿命仍各算各的。客户端表现时长与服务器碰撞窗不共用一个 Duration，也不拿父 Duration 顶没黄帧的碰撞。

## 1.4 发射物（精简；细节见 ballistic / skill_pipeline）

- **早建一弹、改阶段**：对齐 `ballistic` 二阶段先例（同一 SpellUnit 上摘 TrackMove、换行为，不换实体）。
- 握持跟 LaunchPoint 烘焙 → 释放进轨迹 → 再开碰撞：全程操作**同一颗**服务器 Unit。
- **冻结**：PresentUnit / 假球交接、Align 补丁、表现销毁→逻辑创建。客户端只挂外观与拖尾，不另造可交接逻辑球。
- Carrier / 形状 vs 单位：仍按发射点 `Carrier` 与现有 sync 规则；本卡不改代号表。

## 1.7 逻辑形状 / 事件形状

种类看 **Buff 加在谁身上**，不看判断写在树的哪一层，也不看阶段节点是不是唯一挂点。有发射物时客户端播特效，发射物为空时不写客户端创建特效；服务器都用 `BTCastShape`。名字末尾有正整数时形状号用它，没有时用作者填的形状号。

| | 逻辑形状 | 事件形状 |
|---|---|---|
| 父节点 | 施法者（儿子） | 那颗发射物（孙子） |
| 位置 | 施法者挂点。强脱离和弱脱离都让客户端特效停在出手那一帧的世界坐标；强脱离留到自己的时长，弱脱离在所属 Buff 结束时收 | 加 Buff 当时发射物的世界坐标，之后不再跟着骨头，也不跟着人 |
| 触发 | 段上的黄帧，或 00 里的条件 | 同样可以是 00 的条件，或阶段 Children。阶段节点只是其中一个入口 |

盾上炸弹：05 只让炸弹跟着盾骨。引信或靠近由 00 判断。成立后把爆炸 Buff 加在炸弹上，停在炸弹当时的坐标；人再接后摇飞走。炸的那一帧坐标可能和挂点重合，下一帧人已经离开，所以这只爆炸是事件形状，不是逻辑形状。

## 1.5 双端职责

- **客户端动画 Buff 树**：该段动画、根运动开关、表现点 `BTCreateBuffEffect`；不另开「仅表现」Buff 冒充逻辑权威。
- **服务器动画 Buff 树**：该段逻辑、创建 SpellUnit / 业务 Buff、碰撞与命中。
- **00**：姿态锁；切段编排以服务器 AddBuff / 同步为准，客户端跟播。


## 1.6 应然 / 现状 / 待转化器

| 项 | 状态 |
|---|---|
| 一动画片段 = 一个动画 Buff；00 切段编排 | **应然（已定）**，写本卡 |
| 单动画 + 随机变体 01/03/05；00 姿态锁；01 客户端播动画 | **现状**（sync / spec / root_motion） |
| 顺序多段 A→B→C 连续号、本地转自动出 01/02/03 | **待转化器**；号段待对齐 skill_sync 可覆盖号 |
| 一弹改阶段（Hold→Release→Track→Hit） | **应然**；二阶段先例在 ballistic。没有轨迹时的接入持握已写在分阶段节点，运行未验证，见 `spell_unit_bt_phase` |
| Present / 假球交接 / Align | **冻结（已撤）** |

本地转技能树（`skill_sync`）：当前按单动画 / 随机变体路径写 00+动画 Buff；多段顺序路径未接 converter。改 sync 正文以一行交叉引用为限，不在本卡复制整段转化流程。


## 1.8 客户端技能攻击动画（按单位档分流）

**按单位档选 Controller 与播放节点，不按层把两套拧进同一 Controller。** 不要做成「PlayAnim→Upper_Layer、PlayAction→Full_Layer」双路径。

| 单位档 | Controller | 技能攻击节点 |
|---|---|---|
| 简单怪 | Legacy（可无 FullKind） | 只 `BTAnimatorPlayAnim`（单一播放） |
| 精英 / Boss | ParameterAction：独立 `Full_Layer` + `FullKind`/`FullTime` | 只 `BTAnimatorPlayAction`（Attack～Attack4；Loop/Single） |

- 同一单位 `ParameterActionReady` 后禁止再用 `BTAnimatorPlayAnim` 播攻击（Legacy 攻击硬拒、无回退）。升模板的单位：**新技能默认 PlayAction**。
- 怪物施法锁移动时攻击语义是全身 / Full（现路径 Upper=0、Full=1）；Upper 对怪技能价值低，**不全局删**（玩家走攻与存量选层仍可能用到）。
- PlayAction 暂不覆盖 Attack5+/Accident、无 Full 绑定、非技能主 Animator；那些仍走旧入口或其它节点。

## 1.9 编排收口：距离或子 Buff 到期

00 编排「贴脸或冲锋窗结束都进同一收口」时：

- **顺序**：条件满足（距离到达 **或** 子 Buff 到期）→ **先 Remove 子 Buff（若仍在）→ 再 Add 收口 Buff**。收口由 **00 Add**，不要挂在即将 Remove 的子 Buff 下（父死会级联清子）。
- **WaitCondition**：`MaxWaitTime=0` 只等条件、不接超时；要用「条件或到期」时设 `MaxWaitTime`≈子 Duration（秒）并勾选 **SucceedOnTimeout**，成功与超时都继续同一后续。旁路再挂固定 Wait+第二 Add 收口会双触发。
- **爆炸 / 结算类业务 Buff**（如 706）只放在收口 Buff 上；冲锋子树只保留 Chase/表现，不在子树里再 Add 爆炸。

# 2. 坑和不变量

- **不把多段动画塞进同一个 01**；切段逻辑在 00。
- **不按判断所在的节点给形状分类**。00 里做出的爆炸，加在施法者身上才是逻辑形状，加在发射物身上才是事件形状。
- **不因为炸的那一帧和挂点重合，就把爆炸加在人身上。** 人会飞走时，爆炸留在炸弹当时的坐标。后摇播了不等于这只爆炸已经加上：爆炸加在技能体上，技能体没有接上时后摇仍会播。本轮退出有后摇、没有爆炸形状和触发特效，持握未测。
- **不把子业务 / 碰撞寿命写成「= 父 Buff Duration」**；碰撞归节点持续（t043）。
- **不恢复**表现↔逻辑弹交接、时长硬凑、Align 补丁。
- **不把「01/02/03 连续号」写成已实现**：随机 01/03/05 是现状；顺序多段号分配待 sync / converter。
- 根运动：`BTSetRootMotion` 在**被选中的动画 Buff**上，不在 00。
- **技能攻击动画**：按单位档分流见 §1.8；Ready 后禁止 PlayAnim 播攻击；不把 PlayAnim/PlayAction 拧进同一 Controller 分 Upper/Full。
- 应然 / 现状 / 待转化器三者分开写；冲突时以运行验证为准并标疑似过时。

# 3. 怎么验证

- 单段：00 + 一个动画 Buff（现状常为 01）；客户端只播一段；服务器逻辑只挂在该 Buff。
- 多段（转化器就绪后）：00 按序创建 01→02→03；每段自有 LaunchStartTimeMs/Duration；切段与姿态锁策略一致。
- 发射物：一弹从创建到命中无第二次 Create 交接；阶段切换可见于组件 / 日志，而非 Destroy+Create。
- 回归：随机变体 01/03/05 与 root_motion 仍成立；重转不丢「一动画一 Buff」原则说明。
- 攻击节点：简单怪技能树无 PlayAction；已升 ParameterAction 的精英/Boss 技能攻击无 PlayAnim。
