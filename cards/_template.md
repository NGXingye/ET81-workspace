# 0. 职责定位

模块卡模板。一张卡讲清一个模块「怎么转、哪里坑、怎么算对」，目标不超过约 80 行。路径只当证据，不当正文。写入门禁（`allowed_write` / `extra_forbidden`）仍在 `profiles/<id>.md`，卡里只写人话边界。

复制后：`# 0` 写三行速览；未经用户运行验证的条目末尾标「（未验证）」。

> 速览：它做什么（一句）。
> 最大风险：最容易出事的一件事。
> 做对的标准：改完怎样算对。

# 1. 怎么运转

数据流一条线（A → B → C），加不超过 5 个关键入口（文件或类）。

# 2. 坑和不变量

每次改代码前逐条过。一条一行：「不要 X / 必须 Y ——因为 Z」。只收会反复踩、能迁移的；一次性数值放 `# 5`。

# 3. 边界

- 门禁：`profiles/<id>.md`（机器读）。
- 可改：一句话概括目录。
- 禁碰：一句话概括。

# 4. 怎么验证

改完看什么现象 / 跑什么检查算对。

# 5. 证据

来源任务号；必要时附 1–3 个关键路径或配置号。
