# 0. 职责定位

仅当用户在本轮发出 `/harvest` 时执行。这是中途收割：把本单真正学到的东西提炼进 `standards/` 的模块卡。不走冷启动。不必先 `/implement`。不停卡。`/harvests` 的知识部分也按本文 §1 执行。

正路：同窗口，你已验证（fast 小改、`/implement` 之后、或只收分析且你点名）。

拒绝并留在当前阶段：`idle`；刚改编辑器源码且尚未验证（除非你明确只收分析）；仍 `blocked` 且未选择收口。

禁止读取：`global_rules/`、runtime 源码、discovery 读序。本对话已有证据则不要重读游标。新窗口仅当 `phase` 为 `awaiting_verify`，或 `route=fast` 且你点名，或你点名只收分析时，只读游标与 `current_scope.json`。

# 1. 提炼规则

先答三问：

1. **哪里绕了路或判断错了？**（以 `verify_feedback`、被推翻的假设为准）
2. **根因是什么，能不能泛化？** 只属于本模块 → 该卡「坑和不变量」（机制写「怎么运转」，验证方法写「怎么验证」）；两个以上模块都会踩 → `standards/_index.md`「跨模块的坑」。
3. **以后在什么场景会再触发？** 写成那一条的前半句。

写入三条：

- **只加新的**：先在目标卡和跨模块的坑里找同义条目，已有就不加。
- **旧的被推翻就原地改**：需求变了或新验证结果与旧条目矛盾，直接改那一条，不追加第二条并存；废弃的做法删掉。
- **没价值不改**：答不出三问或答案已在卡里，一个字都不改，回复「本单无新增知识」。

另外：

- **控长度（软参考）**：每卡约 80 行是参考，不是硬门槛。超出时先合并重复、删明确过时的；有价值的坑和不变量宁可超出也保留，不为凑行数删内容或压成难懂的缩写。明显超长（约 120 行以上）时考虑拆卡。不写流水账和一次性数值；任务号只在有用处括号注明。
- **未验证标记**：只读过代码、用户未在运行中确认的条目末尾标「（未验证）」，验证后去掉。
- **疑似过时**：任务中被标为「疑似过时」的条目，收割时必须核实，然后原地改正或删除。
- **旧工作副本**：根因是本地 WC 落后于别人的提交时，在「跨模块的坑」补或改一条「分析前先 scoped update」，已有则不加。
- 新模块第一次收割：按 `standards/_index.md` 的卡片格式建 `standards/<模块>.md` 并在索引登记关键词；可写范围或禁区真的变了才改 `profiles/<id>.md`。
