# 0. 职责定位

本文件是 `tools/` 脚本的写法规范。登记与副作用仍见 [`../tools/_index.md`](../tools/_index.md)；准不准碰 SVN/trunk 见 [`code_governance.md`](./code_governance.md)。

# 1. 架构

- 一工具一事。机检与将来的 SVN 脚本不得写进同一入口。
- 政策只写在 `code_governance.md`。脚本不得再写一套「何时可 commit」。
- 禁止为尚未存在的工具先建空框架。仅当**两个入口都要用**同一解析时，才允许已登记的非入口辅助文件（须在 `_index.md` 标明「非独立入口」）。
- 入口脚本只编排：参数 → 调用检查/SVN → 退出码。

# 2. 方法与数据

- 函数单一职责；命名动词-名词。
- `$ErrorActionPreference = 'Stop'`。外部命令非 0 必须停，不得继续写码或提交。
- 机检用错误/警告列表；SVN 用路径列表与退出码。禁止本地数据库或隐藏状态文件。
- 路径只从 `$PSScriptRoot` 推 workspace，从游标读 `source_root`。

# 3. 硬编码与重复

| 允许 | 禁止 |
|---|---|
| 机检错误码 | 账号、密码、仓库 URL、`--force` |
| 与 `kv_budget` 一致的键名 | 再抄 Unity 版本、白名单、提交说明格式 |
| `$PSScriptRoot` 推导的根 | 默认 `$true` 允许 commit |

工程事实以权威 MD 或 `ProjectVersion.txt` 为准。脚本跟随读取，不另写一份版本号。

# 4. 体积与处置

物理行：软上限 180，硬上限 250。超硬上限不得用抬上限或把文件改成 L2 规避。

| 违规 | 只允许 |
|---|---|
| 超 250 行 | 删重复 → 按职责拆成已登记脚本 → 先改 `_index.md` |
| 政策与脚本双写 | 删脚本里的政策，留 MD |
| 未登记 `.ps1/.py` | 删除或先登记再留 |
| 机检 `TOOL_LINE_MAX` / `TOOL_UNREG` | 按上表处理后重跑机检 |
